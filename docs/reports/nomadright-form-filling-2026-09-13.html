1 · How a session runs

Cameraone frame of the form (existing capture; the auto-crop is now rejected when it would cut the page to an inner table)
OCRheader band, English pass 1.5–3 s; the selected script's pass only if needed; a wider English pass as a last try
Identifytitle patterns (verbatim for short ones, fuzzy with a floor for long ones), weighted keywords in three scripts, look-alike discriminators, the conversation's scheme as a small prior
Confirm"Is this the X form?" — yes / no / the person names it; two close candidates → "X or Y?"; nothing readable → "which scheme?"; no fit → the supported list
Askeach field in form order: TTS question → hold-to-talk → ASR → parse → validate → confirm the risky ones; repeat / change / skip / cancel by voice or the four big buttons
Documentsaccount number, IFSC, Aadhaar, PAN, ration or voter card: show the document, press the button, OCR extracts the value (Aadhaar check digit verified, an OCR'd “Q”/“O” in an IFSC's fifth place normalised to the zero it must be), read back; a required value the camera cannot read is asked by voice, an optional one — and the IFSC, which nobody can dictate — is left for the officer (skipped)
Reviewall answers read back; "yes" sends, "change" + a number re-asks that one (switchable)
Seal & sendNaCl-sealed JSON → outbox file → mTLS POST → hash ACK → delete; otherwise retry and tell the person it is saved

Language handling: the selected kiosk language drives the screen, the TTS questions, the ASR model and the retry/clarification messages; the questions and prompts are read from forms.json in that language — the NMT models are not called for any of it. English is offered on the screen but the form flow needs Hindi or Tamil (no English ASR on the device); pressing Camera in English says so.

2 · Identifying the form

Benchmark: 90 synthetic webcam-like photos made from the official PDFs (each form in each available script × six variants) plus six negatives, through the real pipeline — crop, header-band OCR in English, the selected script's pass when English is not conclusive, one wider English pass as a last try — with the identifier's decision rule: accept only with a strong title match, keyword support and a clear margin; otherwise confirm, choose between two, or say it could not read the form. Five iterations of the rule were measured (the first got 8 wrong out of 84 through generic patterns such as “form 1” and a document auto-crop that kept an inner table instead of the page); the final rule is below. 3 · The questions, the answers, the data

Each form's fields are defined once, in order, with a type, whether it is required, its validation, the question in three languages, and — for the sensitive ones — the document to read it from. The session machine (formfill/session.py) walks that list; no model decides the order or the keys. Answers are parsed deterministically: number words and digit sequences in Hindi, Tamil and English, dates in three shapes per language, Aadhaar with its Verhoeff check digit, mobile numbers, PIN codes, choices with per-language synonyms, yes/no, and the command words. Group fields (household members, workers) expand to name / relation / gender / age per member from a spoken count. Three failed attempts on a required field leave it for the officer (listed in the submission as unanswered_required) rather than blocking the person.

Temporary data lives in one dictionary for the session and nowhere else; it is overwritten and dropped on completion, cancel, Home, a language change, or 90 s without the button. The application log carries ids, states, sizes and timings only — the tests fail if a name or number reaches it.

4 · Sealing, transport, the receiver

  • Sealed at completion: the finished form is encrypted with NaCl Box (X25519 + XSalsa20-Poly1305) using the kiosk's private key and the receiver's public key the moment the review is confirmed; the plaintext dictionary is dropped right after. Only the receiver can open it. The sealed file sits in ~/.local/state/nomadright/outbox/ (0700/0600) until acknowledged.
  • Transport: HTTPS with mutual TLS (TLS 1.2+, OpenSSL 3.0): the kiosk verifies the receiver's certificate against the pairing CA and a pinned SHA-256 fingerprint; the receiver accepts only certificates signed by the pairing CA (the kiosk's). No DNS, no internet, no external CA.
  • Acknowledgement: the receiver decrypts, stores the JSON, and answers with the blob's SHA-256; the kiosk deletes its copy only when the hash matches. A repeated send of the same form (same session id) is answered duplicate and not stored twice.
  • Failure: a sealed form is never lost silently - it is retried with backoff, the person is told the office computer is unreachable and that the form is saved, the officer sees the pending/failed counts, and after 24 h it goes to outbox/failed/ still sealed.
  • Logs: the flow and the outbox log ids, states, sizes and timings only; tests assert that names, numbers and Aadhaar values never reach the log stream.
  • Memory: answers live in one dictionary for the session; clear() overwrites and drops them on completion, cancel, Home, language change or timeout.

Setting up the laptop as the receiver

  1. On the Jetson, once: cd ~/Retro/NOMADRIGHT/pocket-infer-sw && python3 tools/pair_receiver.py --receiver-ip <laptop LAN IP> --device-id kiosk-01. This creates a private CA, an mTLS certificate for each side, a NaCl key pair for each side, ~/.config/nomadright/receiver.json (what the kiosk uses; keys and certificates by path, nothing in the source tree) and the folder ~/nomadright-receiver-bundle/.
  2. Copy the bundle folder to the laptop (USB stick or scp -r ~/nomadright-receiver-bundle user@laptop:). It contains receiver.py, receiver.json, the receiver's private key and certificate, the CA certificate and the kiosk's public key - keep the folder private (it is 0600).
  3. On the laptop: Python 3.8+ and pip install pynacl, then cd nomadright-receiver-bundle && python receiver.py. It listens on port 8443 (mTLS - only the paired kiosk's certificate is accepted) and serves the officer's dashboard at http://localhost:8080/ (local browser only; auto-refreshes every 10 s). Received forms are written as JSON under received/<date>/<form>_<session>.json; received/index.json is the log. Allow port 8443 in the laptop firewall for the kiosk's IP only.
  4. Give the laptop a fixed address (DHCP reservation or static IP on the SREC Wi-Fi) - the kiosk config holds that IP and the certificate's SAN is bound to it. If the IP must change, re-run pairing and copy the new bundle.
  5. Restart the kiosk (pocketinfer-retro). The kiosk log shows RECEIVER paired; the dashboard shows last contact within 30 s (the kiosk posts its outbox counts every 30 s while reachable).
  6. Re-pairing / revoking: re-run step 1 and copy the new bundle; the previous certificates stop working immediately because the CA is new. Nothing is shared with any other device or the internet.

Transmission failure and recovery

The receiver unreachable: the person hears "the office computer is not reachable right now, your form is saved safely and will be sent automatically"; the sealed file stays in the outbox; the kiosk retries in the background (10 s, 20 s, 40 s … every 5 min at most) and posts its pending/failed counts to the laptop whenever it can reach it, so the officer's dashboard shows N waiting on the kiosk with the last error. After 24 h the file moves to outbox/failed/, still sealed, and counts as failed. Nothing is retried forever and nothing is deleted before an acknowledgement.

5 · Session cleanup

The existing triggers all end a form in progress and wipe its answers: Home (the flow's listen/capture return immediately and the session is cleared), a language change (same path — a new language is a new person), the scheme-intelligence idle expiry (5 min), and the form's own walk-away timeout (90 s after a question). A completed form is different: it is sealed before anything else happens and only the receiver's acknowledgement removes it; cleanup never touches the outbox. All of this is exercised by the unit and flow tests.

6 · Qwen behind "Ask Chatbot"

The previous camera flow — photo, spoken question, Qwen3-VL answer — is untouched and reachable from the corner button on the Document page. The primary flow never starts the language model: identification is OCR + the catalogue, questions come from the catalogue, answers are parsed by rules. Serving of the chatbot itself was switched earlier today from Ollama to the app's own on-demand llama-server (2.6 s per fresh photo instead of 5.6 s, ~1.2 GB less), which the form flow never starts; it comes up only when someone presses Ask Chatbot and stops five minutes after its last answer.

A full Hindi PMSBY session with fake speech and real OCR: 29 spoken prompts, identification 9.077 s, document OCR 0.512 s per document, 11.3 s in total without the speech itself. The 10-session run's slower identification (9.5 s against 6.2 s for the same photo in the other two runs and 6.1 s in the identification benchmark) coincided with the desktop's update-manager using a core; the Hindi photo takes the English-then-Hindi OCR path, which is the second-slowest of the paths in section 2. Each spoken question costs one TTS synthesis (measured 1.4–1.9 s for a sentence in the e2e voice runs) and one ASR pass on the answer (Hindi Conformer 0.1 s, Tamil Whisper ~1.7 s), so a question-to-answer cycle is about 2–4 s plus the person's speaking time; a 20-field form is a 3–5 minute conversation. The flow runs with bhashini (ASR/NMT/TTS) resident and nothing else: no vision model, no embedder, no extra ASR/TTS instance. 9 · Configuration and rollback

FORM_FILLING_ENABLED
Master switch (constants.py). False restores the previous Camera behaviour (photo + question to the vision model); the flow code stays in place. Rollback in one line.
FORM_REVIEW_ENABLED
Read every answer back before sending (on). False sends as soon as the last field is answered.
FORM_OUTBOX_MAX_AGE_S
How long a sealed, unsent form waits on the kiosk before it is moved to outbox/failed/ and reported as failed on the laptop dashboard: 24 h (24 * 3600.0). Change the number; the retry rhythm is FORM_OUTBOX_RETRY_BASE_S (10 s, doubling) capped at FORM_OUTBOX_RETRY_MAX_S (5 min), retried every FORM_OUTBOX_FLUSH_INTERVAL_S (30 s).
FORM_ANSWER_TIMEOUT_S
How long the kiosk waits for the button after a question before it treats the person as gone, wipes the half-filled form and returns Home (90 s). Home, a language change and the scheme-intelligence 5-minute idle expiry also end a session.
FORM_LANGUAGES
Voice form filling is offered in these languages (hi, ta) - the ones with an ASR model and predefined questions. In English the Camera button explains that Hindi or Tamil must be chosen.
nomadright/forms/build_forms.py → forms.json
The form definitions: title patterns, keywords, fields in form order with type, required flag, validation, the question per language, which document a sensitive field is read from. Edit the builder, run it, restart the kiosk. Strings marked for native-speaker review.

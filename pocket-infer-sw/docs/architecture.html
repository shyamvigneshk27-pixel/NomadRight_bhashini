The Signal Path

NomadRight is a handheld voice assistant for India’s migrant and informal workers — brick‑kiln hands, street vendors, construction labour — who need to know what a welfare scheme like BOCW, MGNREGA, PM‑KISAN or PMJAY actually owes them, spoken back in their own language, with no phone signal required. A worker holds a button, asks a question aloud, and eleven more stages run — speech recognition, two translation hops, a rules‑and‑retrieval decision layer, an on‑device 2B‑parameter LLM, text‑to‑speech — before the speaker answers. Every stage runs locally on the same board. None of them run in parallel.

01 — Runtime Topology

Four processes, one board

Before a single word is spoken, four independent OS processes are already running. The app talks to two of them over plain HTTP — to itself, on localhost — and all the heavy models share one physical memory pool, because Jetson has no separate VRAM.

nomad_right/app.py is the only process a worker’s query actually flows through end‑to‑end. It talks to the touchscreen over a Pipe/Queue RPC, and to the two model services purely over HTTP — even though everything lives on the same board.

bhashini_models.service hosts ASR, NMT and TTS behind Flask’s own development server — not a production WSGI server — so it is single‑request‑at‑a‑time by default.

ollama runs the LLM as its own daemon. It and the BHASHINI models draw from the same unified memory pool with no reservation between them — the code’s own comments describe a real CUDA out‑of‑memory crash this caused before the RAG embedder was pinned to CPU.

02 — The Turn, Stage by Stage

Twelve stages, one hard sequential chain

No stage starts before the last one returns. There is no streaming ASR, no pipelined translation, no pre‑fetched TTS — total turn latency is a straight sum of every box below, not the slowest one.

hardware I/O local service call (HTTP, same board) in‑process CPU subprocess spawn (CLI binary) bottleneck

Scroll horizontally on narrow screens. The red ring marks stage 08 — Qwen generation — the only stage whose worst case is measured in minutes, not seconds.

03 — Nook and Corner

What each stage actually does

Grouped the way the code groups itself — capture, bridge languages in, take a shortcut if one exists, decide, generate, bridge languages back out, speak.

Phase A

Capture & Bridge In

01–02hardware

Trigger & Audio Capture

boards/jetson.py · boards/base.py

A GPIO interrupt fires on button‑down and sets a threading.Event — event‑driven, no polling loop. The mic records for exactly as long as the worker holds the button; that duration isn’t counted against turn latency, which starts on button‑up.

instant trigger · variable capture
03local service

ASR — Speech to Text

bhashini_bridge.py → asr/infer.py

A blocking HTTP call to the on‑device BHASHINI service, which runs an ONNX conformer + CTC decoder on the Jetson GPU. Models load once at service startup and stay resident. Only Hindi and Tamil sessions actually exist.

0.3s warm · 5.7s cold
Risk — SOURCE_LANGUAGES advertises 7 codes (hi, ta, or, bho, mai, sat, hne); the ASR service only loads sessions for 2. An unsupported code raises an uncaught exception that a blanket except turns into a silent empty result.
04local service

NMT‑IN — Native → English

bhashini_bridge.py → nmt/infer.py

A second blocking HTTP call, CTranslate2 int8 models on GPU. The Decision Layer downstream is English‑only regex matching, so this hop is load‑bearing for every query.

≤15s timeout
Risk — on failure this returns the untranslated source text rather than an error. Five languages (bho, mai, hne, awa, mag) have no dedicated model and are silently rerouted through Hindi’s.
Phase B

Fast Paths

05in‑process

Shortcut Checks

app.py · scenario_cache.py

Three checks run before the full Decision Layer: a pending‑photo follow‑up (routes straight to vision Qwen), a curated scenario cache (embedding match, ≥0.93 similarity, currently 3 entries — all PDS), and an official‑translation bridge for TRANSLATION_REQUEST intents. Any hit skips everything below.

0.2s warm · 4.9s cold
Phase C

Decision Layer

06in‑process

Intent · Entities · SQLite

intent.py · entities.py · classifier.py · database.py

Pure Python, CPU only: a regex cascade for intent, gazetteer extraction for entities, and a SQLite lookup against all 20 schemes’ records — preloaded into an in‑process dict cache at startup, so this is an L1 hit, not a disk read.

< 2ms
07in‑process

Rules Engine & RAG Retrieval

rules.py · rag_pipeline.py

Four schemes (PDS, PMJAY, eShram, BOCW) have a deterministic, hallucination‑safe rules branch. The other 16 fall to ChromaDB retrieval — a 118M‑param multilingual‑e5 embedder, forced onto CPU to avoid GPU contention with Qwen, top‑3 chunks above a 0.83 cosine floor.

rules <1ms · RAG ~100s ms
Risk — the code’s own tuning notes put legitimate queries at 0.83–0.88 similarity and garbled ones at 0.79–0.84 — the cutoff sits inside the overlap. Index warm‑up costs 10–140s, paid once at boot.
Phase D

Generation

08bottleneck

Qwen LLM (Ollama)

qwen_client.py → ollama :11434

A 2B‑parameter Qwen3‑VL GGUF model, forced to full GPU offload (num_gpu=99) because Ollama’s auto‑fit heuristic otherwise offloads nothing once BHASHINI holds memory. Called on every RAG‑routed query above threshold, every rules‑and‑RAG miss, and every camera‑photo read — not the “narrow, explicitly‑gated” case the module docstring describes.

1–3s warm · ~53s evicted · 108–242s cold
Risk — a single blocking call, no streaming, no retry. The 220s timeout exists specifically because a real on‑device run took >150s and was nearly cut off. Cancellation is checkpoint‑based — a worker pressing Home mid‑call still waits for it to finish.
Phase E

Bridge Out & Delivery

09in‑process

Response Synthesis

response.py

A six‑tier priority chain (rules → RAG+Qwen → LLM fallback → raw RAG template → KB‑only → generic) picks the final answer text and formats it for TTS and the LCD.

< 1ms
10local service

NMT‑OUT — English → Native

bhashini_bridge.py → nmt/infer.py

The mirror of stage 04, translating the composed answer back to the worker’s language before synthesis.

≤15s timeout
11subprocess

Text‑to‑Speech

bhashini_bridge.py · tts/infer.py

Flite synthesizes over a CLI subprocess + temp file. An optional voice‑styling pass then runs a second subprocess — ffmpeg, a five‑stage filter chain (pitch/tempo, highpass, dual EQ, compressor, loudnorm) — with its own temp files. Both run on every single answer.

flite + ffmpeg ×2
Risk — or (Odia) is an advertised source language with no entry in the TTS voice map at all.
12hardware

Playback

audio.AudioPlayer · ffplay

Plays over the speaker via ffplay, interruptible by the Home button; the LCD shows the question and answer together. Playback time isn’t counted against the response‑time budget, but the device is occupied until it finishes or is stopped.

not budgeted

05 — Diagnostic Log

Where the design is fragile

Seventeen findings from a static read of the source, ranked by how badly each one can go wrong for a worker mid‑query — not by how easy each is to fix.

Critical
CRITICAL
The pipeline never overlaps a single stage with the next
ASR, both NMT hops, retrieval, generation, and TTS run one after another with no pipelining or pre‑fetching. Total turn time is a straight sum of every stage, so any one slow stage delays all the fast ones behind it.
app.py::run()
CRITICAL
Qwen cold‑load and eviction can cost minutes, not seconds
Observed cold loads of 108–242s, and a ~53s reload after 15 minutes idle. Against a 220s timeout, a worker can face over three minutes of silence with no progress indication beyond a static status line.
qwen_client.py · constants.py
CRITICAL
Unsupported ASR languages fail silently
Five of seven advertised source languages have no ONNX session. An unsupported code raises an uncaught exception server‑side; the client’s blanket except turns it into a blank “ask again” screen with no diagnostic trail beyond a generic log line.
bhashini_models/asr/infer.py · models/asr.py
CRITICAL
No text‑to‑speech voice exists for Odia
or is a listed source language with no entry in the TTS voice map — even a correct Odia answer has nothing to speak it back with.
bhashini_models/tts/infer.py
CRITICAL
A live model call can’t be cancelled
Home‑button cancellation is checkpoint‑based. A worker who wants out of a 220‑second Qwen call has to wait for it to return anyway.
app.py

Translation failures degrade silently
A broken NMT call returns the untranslated source text instead of an error, so a native‑language sentence can reach the English‑only regex intent recognizer untouched, silently degrading to a wrong route.

Five languages borrow someone else’s translation model
Bhojpuri, Maithili, Chhattisgarhi, Awadhi and Magahi are silently routed through the Hindi NMT model; Santali through Odia’s. No dedicated model, no disclosure to the worker that the translation is an approximation.

Qwen runs far more often than the code claims it does
The module docstring frames the LLM as a “narrow, explicitly‑gated” fallback, but the RAG route calls it on nearly every query for 16 of the 20 schemes — not just true misses.

The code’s own tuning notes put legitimate queries at 0.83–0.88 cosine similarity and garbled ones at 0.79–0.84. The 0.83 threshold lives inside that overlap, so both false‑accepts and false‑rejects are expected by design.
